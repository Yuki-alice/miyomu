### 主要风险（按杠杆排序）
1. **CI 从首个提交起全红**（KSP 2.3.12 在 GitHub runner 解析失败，本地可解析）。合并门禁为零，
   而项目是「两台机器 + 夜间 goal 窗口」并行模式 —— 这是最系统性的风险。
2. **`feature/novel` 在腐化**：11 commits 领先 / 26 落后 main，84 文件 +7,353 行；
   且它动过 `MiyomuApp` 接线与 `MiyomuAppTest`，正好撞上 AGENTS.md 的「单一 schema owner」
   高churn 文件，rebase 冲突几乎必然。拖延成本随时间线性上升。
3. **「完成」≠「可交付」**：无 jpackage 配置（msi/dmg 都没有）、Windows 端 MPV 未实机验证、
   无 tag 无 release。所有 Phase 成果目前只有本机能跑。
4. 文档债：`03-risk-register.md` 停在 2026-10-28（Phase D 前）、`01-architecture.md` 模块列表
   早于 Phase D；三份交接文档（09/10/11）并存。

的决断 → ③ 先打一个 0.1.0 包 + tag，让「完成」可被第三方验证。
