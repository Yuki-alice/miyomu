## 10. Git 推送配置（本机环境问题，勿再踩）

现象：`git push` 报 `remote: No anonymous write access. fatal: Authentication failed for 'https://gh-proxy.com/https://github.com/Yuki-alice/miyomu.git/'`。

根因：`~/.gitconfig` 有一条全局镜像规则

```
url.https://gh-proxy.com/https://github.com/.insteadOf = https://github.com/
```

它把所有 `https://github.com/` 的地址改写成 gh-proxy 镜像。该镜像**只允许匿名读取**，因此 `fetch`/`ls-remote` 正常，`push` 必然失败——和凭据是否存在无关（GitHub 的凭据在凭据管理器里是有的）。

解决方案：再加一条只作用于推送的全局规则，让 push 走直连：

```bash
git config --global "url.https://github.com:443/.pushInsteadOf" "https://github.com/"
```

`pushInsteadOf` 只影响推送 URL，`fetch` 仍然走镜像，两者互不干扰。`github.com:443` 带端口的形式不会再被上面的 `insteadOf` 规则二次匹配，所以能绕开改写。配好后 `git remote -v` 会显示 push 地址为 `https://github.com:443/Yuki-alice/miyomu.git`，此时直接 `git push` 即可。

注意：这个规则是**全局**的，会影响本机所有指向 github.com 的仓库；但方向是对的（读走镜像、写走直连），一般不需要清理。仓库级的 `remote.origin.pushurl` 临时方案已删除，不要再加回去——它会和全局规则叠加，增加困惑。
