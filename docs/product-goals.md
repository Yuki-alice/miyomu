## 3. 产品定位候选

| 定位 | 核心用户 | 核心价值 | 范围 | 风险 |
|---|---|---|---|---|
| **A. 个人跨平台媒体库（推荐）** | 有本地收藏、追求离线与隐私的个人用户 | 一个库统一管理漫画/小说/视频；Android + Desktop；本地优先，在线源可选 | 中 | 需要把本地导入、阅读/播放体验做到很好 |
| **B. 阅读优先** | 漫画/小说重度读者 | 最好的跨端阅读体验、书库管理、同步 | 中偏窄 | 视频与源生态投入被压缩 |
| **C. 动漫视频优先** | 追番用户 | 在线源、播放器、弹幕、下载 | 中偏窄 | 与成熟播放器/客户端竞争 |
| **D. 通用二次元聚合** | 大众二次元用户 | 追番/追漫/社区/推荐/追踪 | 大 | 合规、运营、内容、成本都不可控 |

**确认结果：采用 A 的增强版——“Mihon-like + 本地增强 + 视频/小说一等公民”。**

具体含义：

- **Mihon 基线**：漫画库、源/扩展安装与管理、下载、备份、阅读设置、历史/更新等体验，以 Mihon 为参照。
- **本地增强**：本地格式、导入、元数据、封面、分类、离线、备份/同步做得比 Mihon 更深。
- **视频/小说一等公民**：不是附属功能，而是与漫画并列的书架类型、阅读/播放体验和下载能力。
- **不做通用聚合**：不做社区、推荐流、账号体系或内容平台。

理由：

- 当前代码的重心已经在“本地库 + 统一媒体类型 + 双端”，这是最难被替代的部分。
- 在线源是重要能力，但作为**可选插件**比作为产品核心更可持续；避免把维护成本和合规风险绑死。
- 视频播放器保留，但不追求成为“流媒体平台”；弹幕是加分项，不是主战场。
- 漫画 + 小说的阅读器是最能形成日常使用习惯的场景，也是当前测试与代码投入最多的部分。

## 4. 推荐定位与目标

### 4.1 一句话定位

> **Miyomu 是一个以 Mihon 式漫画库为基线、把本地功能做深、同时支持视频与小说的跨 Android/Desktop 个人媒体库。**

### 4.2 目标用户

1. **Mihon/Tachiyomi 用户**：熟悉源/扩展、书架分类、下载、备份与阅读设置，希望有一个能同时管理视频和小说的继任工具。
2. **本地收藏者**：有大量 CBZ/7z/PDF/EPUB/TXT/视频文件，想要一个统一、离线、可备份的库。
3. **多设备读者/观众**：Android 通勤阅读，Desktop 大屏阅读/整理/播放；两端都应是一等公民。
4. **源用户**：愿意自行安装 JS/Legado 源，用全局搜索发现内容，并下载到本地离线阅读。

### 4.3 用户任务（JTBD）

- “把我的本地漫画/小说/视频扫进来，自动分章、生成封面、记住我读到哪。”
- “在手机上继续桌面上的进度，不要手动找章节。”
- “我想看的内容如果本地没有，可以用自己安装的源搜索并下载。”
- “我的书库和进度不能丢；换设备/重装后能恢复。”
- “阅读时不要卡、不要丢位置、不要被无关功能打扰。”

### 4.4 价值主张

- **Mihon 基线**：保留成熟的漫画库、源/扩展、下载、备份与阅读设置体验，降低迁移成本。
- **本地增强**：本地格式、导入、元数据、封面、分类、离线与备份比 Mihon 更深。
- **统一**：漫画、小说、视频一个库，而不是三个 App。
- **一等公民**：视频与小说拥有独立的书架、详情、阅读/播放、下载与进度，不是附属功能。
- **跨端同等**：Android 与 Desktop 共享书架、进度、分类；两端都按一等公民投入。
- **可控**：无账号、无广告、无云端锁定；备份格式开放。
- **阅读体验**：翻页/Webtoon/分页、章节管理、书签、主题、位置恢复。

## 5. 功能目标

> 优先级定义：**P0** = 没有它产品不成立；**P1** = 形成差异化/显著提升留存；**P2** = 生态或规模化后再做。

### 5.1 P0（核心价值）

| # | 功能 | 范围 | 验收标准 |
|---|---|---|---|
| P0-1 | 本地库导入与扫描 | 漫画目录/ZIP/CBZ/7z/CB7/PDF；小说 TXT/EPUB；视频文件/剧集/Season；Android SAF + Desktop 目录 | 扫描成功率高；失败有可见错误；重复扫描幂等；扫描到的格式都能打开 |
| P0-2 | 统一书架 | 漫画/小说/视频、分类、筛选、排序、搜索、更新、历史 | 三类媒体在同一套导航下可用；分类可编辑 |
| P0-3 | 漫画阅读器 | 翻页/纵向/Webtoon/LTR/RTL、裁剪、转场、位置恢复、双页（按现有能力） | 打开 500 页章节不崩；旋转/返回不丢位置 |
| P0-4 | 小说阅读器 | TXT/EPUB、章节、分页、书签、字体/主题/行距、位置恢复 | 大文件可打开；字符偏移恢复准确 |
| P0-5 | 视频播放 | 本地/在线、音轨/字幕/倍速、下一集、弹幕开关 | Android/Desktop 支持矩阵明确；不支持时给出提示 |
| P0-6 | 在线源与全局搜索（Mihon 式） | Aniyomi JS、Legado 小说、源仓库安装/更新/卸载、全局搜索 | 源安装成功/失败可诊断；单源失败不影响其他源；扩展管理可更新/回滚 |
| P0-7 | 下载与离线 | 漫画章节下载、断点续传、队列管理 | 杀进程后可恢复；空间不足有提示 |
| P0-8 | 备份与恢复 | JSON 备份、WebDAV 上传/下载、版本校验 | 换设备可恢复书架/进度/书签；失败不破坏本地数据 |
| P0-9 | 双端同等 | Android + Desktop 构建、测试、发布流程；两端功能矩阵对齐（Linux 视频后端为已确认例外） | CI 双端通过；平台差异有文档；Desktop 不是二等公民 |
| P0-10 | 基础质量 | 导航可恢复、服务生命周期、无主线程阻塞、崩溃可诊断 | 旋转/进程死亡不丢页；无 ANR；关键路径有测试 |
| P0-11 | 本地库管理深度 | 元数据、封面、分类、重复/缺失检测、存储占用 | 用户不依赖外部工具即可整理本地库 |

> - **P1-3 已完成（基础）**：书架多选批量编辑作者/简介。标签字段已实现（LibraryItem.tags + Room v5 迁移 + 备份兼容 + 批量编辑）；封面候选已实现（目录漫画的顶层图片枚举 + 详情页点选 + 偏好存储覆盖解析），P1-3 全部子项完成。

| 维度 | 目标 |

## 8. 合规与安全边界

- **不托管内容**：Miyomu 只提供本地库管理与用户自行安装的源运行时；不运营内容 CDN、不提供源索引市场。
- **源由用户自行添加**：安装源时明确提示“源来自第三方，用户自行承担合规责任”；保留来源 URL、版本、哈希。
- **源沙箱**：JS 运行时已有超时、内存限制、响应大小限制；目标架构需明确网络、文件、Cookie 的权限边界。
- **备份**：当前 JSON 明文；P1 增加可选加密，并在 UI 中说明 WebDAV 凭据的存储方式。
- **公开分发前**：需要法务复核、滥用举报渠道、DMCA/下架流程；如果无法承担，保持个人/小范围分发。
- **许可**：Apache-2.0；继续保留 NOTICE；不引入 GPL 运行时代码；Linux 视频已确认不做。
